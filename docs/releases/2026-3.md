    #### 🗃️ CANFAR Data Access Beta

    CANFAR Data is a [fsspec](https://filesystem-spec.readthedocs.io/en/latest/) compliant storage adapter that will be available in beta to all CANFAR users with Python client v1.5.0+. The beta includes the `canfar data` commands and the Python storage tools in `canfar.storage`. Your existing storage permissions still apply.

    List, inspect, copy, move, and remove files across local and remote storage
    (`arc`, `vault`, `local`). Every path starts with `IDENTIFIER:/PATH`.
    Remote storage requires authentication; `local` does not.

    ```bash
    canfar login cadc
    canfar data ls -lh arc:/home/USER
    canfar data cp local:/data/input.fits arc:/home/USER/input.fits
    canfar data cp -R vault:/project/cubes local:/data/cubes
    ```

    In Python, call `identifiers()` to list configured storage and
    `filesystem()` for a standard fsspec filesystem:

    ```python
    from canfar.storage import filesystem, identifiers

    print(identifiers())  # ['arc', 'vault', 'local']

    arc = filesystem("arc")
    try:
        print(arc.ls("/home/USER", detail=False))
        arc.put_file("/data/input.fits", "/home/USER/input.fits")
        arc.get_file("/home/USER/result.fits", "/data/result.fits")
    finally:
        arc.close()
    ```

    See [Data commands](../cli/data.md) and the [Python data guide](../client/data.md) for more details.

    #### ➜] Login, discovery, and server limits

    `canfar.login()` and `canfar.alogin()` run browser-based device login from
    Python, save discovered servers, and return `True` when authenticated.
    Select your identity and server before launching Sessions:

    ```python
    import canfar
    from canfar import authentication, server

    canfar.login("cadc")
    authentication.use("cadc")
    server.use("canfar")
    ```

    `canfar server ls` shows each server's CPU, memory, GPU, and interactive
    Session limits for fixed and flexible Sessions. `canfar create` validates
    `--cpu`, `--memory`, and `--gpu` against the active server's limits before
    sending the request:

    ```text
                                              Known Servers

      Name     URI / URL                        Version   Flexible     Fixed        GPUs   Sessions
     ───────────────────────────────────────────────────────────────────────────────────────────────
      canfar   ivo://cadc.nrc.ca/skaha          v1        1-16 cores   1-16 cores   1-7    3
               https://ws-uv.canfar.net/skaha             4-32 GB      1-192 GB
    ```

    #### 📋 Session Management

    Renew interactive Sessions from the CLI or Python (matching the Science
    Portal):

    ```bash
    canfar renew SESSION_ID
    ```

    ```python
    session.renew("SESSION_ID")
    ```

    All `session` methods support `errors="raise"` (or `CANFAR_ERRORS=raise`)
    to raise `SessionRequestError` with partial results when any request fails,
    instead of only logging and continuing.

    #### Updates for existing scripts and CLI workflows

    - Machine output is `-o json` or `-o yaml` on supported commands (replaces
      `--json` / `--yaml`). Stdout is the payload; logs go to stderr.
    - Logging: `-v` for one line per Science Platform HTTP response, `-vv` for
      debug, and `--log-file PATH` for rotating JSON Lines logs.
    - `canfar` obtains CADC certificates directly and no longer installs
      `cadcutils`. If you run `cadc-get-cert` yourself, install it with
      `pip install cadcutils`.
    - `fetch()` accepts only `kind` and `status` (`view="all"` was removed).

    [upgrade guide](../client/migration.md) for the full client change list.

    ### 📦 Deployment Notes
    - Helm charts accept custom annotations.
    - posix-mapper — fixed a caching issue that could make groups collide. New Keycloak-based version of posix-mapper expected in CanfarSP 2026.4.
    - For updated deployment instructions, refer to the [OpenCADC Deployments repository](https://github.com/opencadc/deployments).
    - The Harbor instance at https://images.canfar.net has been upgraded to version 2.15.0. This version has one change that affects deployments: helm charts can only be served as standard OCI objects. So, instead of adding repositories with `helm add`, they must be installed directly with `helm install`.

    The old method:
    ```bash
    helm repo add science-platform https://images.opencadc.org/chartrepo/platform
    helm repo add science-client https://images.opencadc.org/chartrepo/client
    helm repo update
    helm install science-platform/cavern
    ....
    helm install science-client/storageui
    ```
    The new method:
    ```bash
    helm install oci://images.opencadc.org/platform/cavern
    helm install oci://images.opencadc.org/platform/science-portal
    helm install oci://images.opencadc.org/platform/skaha
    helm install oci://images.opencadc.org/platform/posix-mapper
    helm install oci://images.opencadc.org/client/storage-ui
    ```
